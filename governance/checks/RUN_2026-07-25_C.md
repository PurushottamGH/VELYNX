**The 15 collection errors are pre-existing and are not caused by this sprint.** Every one is an `ImportError: cannot import name … from 'p1_os.schemas' (unknown location)` raised while collecting `tests/p1_os/**`. The directory `tests/p1_os/` shadows the real package at `p1/tooling/p1_os/` when the whole tree is collected in one pytest session; the same files pass when `tests/p1_os` is the only argument. Reproduced with `--ignore=tests/governance`, which removes every file this sprint added and leaves all 15 errors in place.

Without `--continue-on-collection-errors` the whole-repository run **aborts at collection and executes nothing**. That is reported here rather than worked around: repairing it means restructuring test packages under `tests/` and `research/tests/` that this sprint does not otherwise touch, and `--import-mode=importlib` trades these 15 errors for 8 different ones. Recorded as `AUT-5` in `05_RELEASE_CANDIDATE_CHECKLIST.md`, non-gating, because no governance artifact cites `pytest` output as conformance evidence.
