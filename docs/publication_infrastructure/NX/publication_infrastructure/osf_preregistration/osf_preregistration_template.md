## 2. H* Preregistration (E0) — Template

### 2.1 Metadata
| Field | Value |
|-------|-------|
| Title | "Error-Gated Structure Acquisition vs. Designer Injection: A Null-Referenced Test" |
| Authors | [Name, ORCID, Affiliation] |
| Date | 2026-XX-XX (pre-experiment) |
| License | CC-BY-4.0 |
| Registration Type | OSF-Standard |
| Embargo | None |

### 2.2 Hypotheses

**H* (Central Hypothesis: Error-Gated Structure Acquisition)**
An agent whose only learning signal is sensorimotor prediction error, and which adds representational capacity only when prediction error persists, will acquire internal structure that:
(i) is absent at initialization,
(ii) improves prediction on held-out data beyond a fixed-capacity control and a capacity-matched control whose growth is decoupled from error, and
(iii) is not reducible to the statistics injected by the designer.

### 2.3 Design

**Experimental Design:** 4 (conditions) × 5 (seeds) factorial

| Condition | Description | Growth |
|-----------|-------------|--------|
| T (Treatment) | Error-gated growth | Triggered by G = H_before - H_after - λ_model > 0 |
| C1 (Control 1) | Fixed capacity | No growth |
| C2 (Control 2) | Capacity-matched random growth | Random times, matched to T growth count |
| C3 (Control 3) | Shuffled input | Destroys temporal structure, preserves marginals |

**Random Assignment:** Seeds randomized; conditions run in counterbalanced order
**Blinding:** Analysis code is independent of condition labels (run by separate process)

### 2.4 Sampling Plan

**Sample Size (per condition):** N = 5 seeds
- Justification: Minimum for stable variance estimate; consistent with NeurIPS standards
- Power analysis: For d = 1.0 (expected large effect), α = 0.01, power = 0.80, minimum N = 5 per group (G*Power)

**Data Collection Procedures:**
- Synthetic data generated by `experiments/E0/dataset.py` with seed
- No data collection stopping rules
- All seeds pre-registered: [42, 123, 456, 789, 999]

### 2.5 Variables

**Independent Variable:** Condition (T, C1, C2, C3)
**Dependent Variables:**
- DV-a: Held-out predictive log-likelihood (continuous, higher = better)
- DV-b: Emergence statistic M(θₖ) = NMI(learned_partition, true_latent) - NMI(learned_partition, C3_shuffled)

**Pre-registered Margin for DV-b:** Δ = 0.05 (to be set based on pilot; minimum meaningful effect)

### 2.6 Analysis Plan

**Primary Analysis (DV-a):**
- One-way ANOVA (or Kruskal-Wallis if non-normal) across 4 conditions
- Planned contrasts: T vs C1, T vs C2 (Holm-Bonferroni corrected, α_adj = 0.025)
- Effect size: Cohen's d with 95% CI
- Bayesian t-test: BF₁₀

**Primary Analysis (DV-b):**
- One-sample t-test of M(θₖ)_T against 0 (null from C3)
- Test against pre-registered margin: M(θₖ)_T - M(θₖ)_C3 > Δ
- Effect size: Cohen's d

**Kill Criteria (from `foundation/kill_criteria/kill_criteria.md`):**
- K1: T > C1 on DV-a at p < 0.01
- K2: T > C2 on DV-a at p < 0.01
- K3: DV-b > pre-registered margin Δ
- **Overall H* verdict: PASS if all 3 PASS; FAIL otherwise**

**Secondary Analyses:**
- Sensitivity: λ_model sweep, K sweep, mixing function sweep
- Assumption checks: Shapiro-Wilk, Levene, Q-Q plots

**Exploratory Analyses (not pre-registered):**
- N/A (or list any explicitly)

### 2.7 Outliers

**Outlier Handling:** Pre-registered inclusion criteria
- Seeds that fail to complete (e.g., NaN, timeout) are excluded with reason logged
- No outlier removal based on results
- All raw data reported

### 2.8 Missing Data

**Missing Data Handling:**
- Seeds that crash: excluded with reason; reported in `results/E0/excluded_seeds.log`
- No imputation
- If >1 seed excluded per condition, report and discuss

### 2.9 Other

**Pre-registration Deviations:** Any deviations from this plan will be:
1. Logged in `experiments/E0/preregistration_deviations.md`
2. Justified with reason
3. Reported in paper as a "Deviations from Pre-registration" section
4. Effect on conclusions assessed

**Materials:** All code, data, and analysis scripts deposited on GitHub + Zenodo with DOI
**Ethics:** No human subjects; synthetic data only; no IRB required
**Conflicts of Interest:** None declared

## 3. H1 Preregistration (EXP-1) — Template

### 3.1 Metadata
| Field | Value |
|-------|-------|
| Title | "Calibration of Uncertainty Tiers: A Reliability-Diagram Test" |
| Date | 2026-XX-XX |
| License | CC-BY-4.0 |
| Registration Type | OSF-Standard |

### 3.2 Hypothesis

**H1 (Calibration):** A retrieval agent can report uncertainty tiers whose empirical correctness matches the tier.

**Operationalization:**
- Tier assignment: CERTAIN (≥0.95), PROBABLE [0.7, 0.95), DEBATED [0.3, 0.7), UNKNOWN (<0.3)
- ECE < 0.1 with 10-bin binning
- Better than constant-confidence baseline

### 3.3 Design

**Query Set:** N = 200+ mixed queries
- 50% known facts (from ArXiv, Wikipedia with known answers)
- 25% ambiguous questions (multiple valid answers)
- 25% hallucination traps (no valid answer exists in source)

**Protocol:**
- Each query → tier + answer
- Compare tier confidence to empirical accuracy
- Compute ECE

### 3.4 Variables

**Independent Variable:** Tier (CERTAIN, PROBABLE, DEBATED, UNKNOWN)
**Dependent Variable:** ECE (Expected Calibration Error)
**Baseline:** Constant confidence = empirical accuracy

### 3.5 Analysis Plan

**Primary:** ECE with 95% bootstrap CI (10000 resamples)
**Kill Criteria:**
- K1: ECE < 0.1
- K2: Better than constant baseline (ΔECE < 0, paired bootstrap)
- K3: 0 CERTAIN predictions on hallucination traps

### 3.6 Sample Size
N = 200 queries (minimum for stable ECE; consistent with prior calibration literature)
N = 500 if possible (for tighter CI)

## 4. H2 Preregistration (EXP-2) — Template

### 4.1 Metadata
| Field | Value |
|-------|-------|
| Title | "Affective Framing as Retrieval Key for Problem-Solving Schemas" |
| Date | 2026-XX-XX |
| License | CC-BY-4.0 |
| Registration Type | OSF-Standard |

### 4.2 Hypothesis

**H2 (Affective Indexing):** A learned affective-framing to problem-solving-schema mapping improves objective task outcomes over an unframed baseline.

### 4.3 Design

**Task Suite:** N = 30+ objective tasks across domains
- Debugging (10 tasks): Objective rubric (tests pass/fail, bug count)
- Planning (10 tasks): Objective rubric (plan validity, efficiency)
- Reasoning (10 tasks): Objective rubric (answer correctness)

**Conditions:**
- T (Framed): Prompt includes affective state → schema mapping (e.g., "shame → debugging → Schema X")
- C (Unframed): Prompt includes only neutral task description

**Randomization:** Task order counterbalanced; condition order counterbalanced

### 4.4 Variables

**Independent Variable:** Frame (present vs absent)
**Dependent Variable:** Objective task score (0–1 or domain-specific scale)

### 4.5 Analysis Plan

**Primary:** Paired t-test (or Wilcoxon signed-rank if non-normal) of Framed vs Unframed per task
- Effect size: Cohen's d with 95% CI
- Bayesian: BF₁₀

**Kill Criteria:**
- K1: p < 0.05 (Framed > Unframed)
- K2: d > 0.2 (meaningful effect)
- K3: No re-authoring of schemas per task (fixed schema library)

### 4.6 Sample Size
N = 30 tasks × 5 seeds = 150 paired observations
Power: For d = 0.3 (small), α = 0.05, power = 0.80, minimum N = 90 (G*Power)

## 5. H3 Preregistration (EXP-3) — Template

### 5.1 Metadata
| Field | Value |
|-------|-------|
| Title | "Emergent Structure Transfer in a Minimal Predictive Organism" |
| Date | 2026-XX-XX |
| License | CC-BY-4.0 |
| Registration Type | OSF-Standard |

### 5.2 Hypothesis

**H3 (Emergent Development):** An agent minimizing sensorimotor prediction error, adding capacity only on persistent error, spontaneously develops reusable structure absent at initialization.

**Note:** EXP-3 is precursor to E0. E0 is the rigorous version.

### 5.3 Design

**Environment:** Task A (training) and Task B (held-out) sharing latent structure
**Treatment:** Error-gated growth
**Control:** Random initialization, no growth during Task A

**Transfer Metric:** Held-out LL on Task B after Task A training

### 5.4 Analysis Plan

**Primary:** Independent samples t-test (Emergent vs Random init)
- Effect size: Cohen's d

**Kill Criteria:**
- K1: p < 0.05 (Emergent > Random)
- K2: d > 0.3
- K3: Structure not trivially explained by initialization + input stats

## 6. OSF Registration Workflow

### 6.1 Steps
1. Create OSF project: https://osf.io/
2. Add components for each hypothesis (H*, H1, H2, H3)
3. Fill pre-registration template for each
4. Add files: protocol, analysis plan, preregistration PDF
5. Make registrations public (no embargo for open science)
6. Lock registrations (cannot be edited after lock)
7. Link to GitHub repository and Zenodo DOIs
8. Add collaborators with appropriate permissions

### 6.2 Required Files Per Component
- `preregistration.pdf` — This template filled in
- `protocol.pdf` — Full experimental protocol
- `analysis_plan.pdf` — Detailed statistical analysis plan
- `code_link.txt` — GitHub commit hash
- `data_link.txt` — Zenodo DOI (post-experiment)

### 6.3 Post-Experiment Updates
After running experiments:
1. Add results to OSF component
2. Create "Results" wiki page with summary
3. Add deviation log if any
4. Add kill criteria evaluation
5. Add Zenodo DOI for data/figures
6. Add paper DOI if published

## 8. Common Pre-Registration Mistakes (Avoid)

1. **Post-hoc hypothesis changes** — Lock pre-registration before seeing data
2. **Vague primary analyses** — Specify exact tests, α, correction
3. **No effect size** — Required for power analysis and interpretation
4. **No sample size justification** — Always include G*Power output
5. **No outlier/missing data plan** — Pre-specify
6. **No deviation plan** — Specify how deviations will be handled
7. **Too many exploratory analyses** — Distinguish from pre-registered
8. **Missing data deposit plan** — Specify Zenodo DOIs
9. **No materials/code deposit** — Specify GitHub commit
10. **Embargo > 0** — Use no embargo for open science (default)
